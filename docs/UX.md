# 交互说明

## 打开仓库

应用首页要求选择已初始化的 Git 仓库根目录。若选择普通目录或仓库子目录，
界面会显示错误，不会退回到父仓库继续操作。

Windows 端使用系统标准“打开”文件对话框导航到目标目录，确认按钮显示为
“打开”，不再使用“浏览文件夹”对话框。打开项目后，顶部“项目目录”按钮可直接
在 Windows 资源管理器中打开仓库根目录。

## 最近仓库

成功打开仓库后，启动页显示该仓库卡片，包括项目名、完整路径和最后打开时间。
单击卡片直接打开；右侧关闭按钮只移除历史记录，不删除仓库文件。记录按最近打开
时间排序并自动去重，失效路径在下次加载时移除，最多保留 10 条。

## 双面板模型

- 左右面板共享同一个仓库根，但各自维护当前目录、加载状态与选择集合。
- 点击任一面板内部区域会把它设为活动面板；活动面板决定粘贴目标。
- 复选框区负责任务选择，双击文件夹负责进入。
- 选中状态在面板导航时保留，因此可以跨目录累计批量任务。

## 剪贴板

剪贴板保存仓库相对路径和模式：

- 剪切：粘贴时移动；
- 复制：粘贴时通过 Git 索引复制；
- 粘贴只把移动或复制步骤加入执行计划，并清空当前剪贴板；
- 点击剪贴板旁的小叉可主动清空。

## 待执行操作计划

所有会修改仓库的入口都先记录为计划步骤：

- 移动、复制、重命名和删除；
- 暂存全部、取消暂存和提交；
- 推送当前分支、单项推送和全部推送；
- 添加、修改、移除远端；
- 清空远端历史并保留一个空提交。

文件工具栏、提交工作区和远端管理窗口都有“待执行 N”入口。计划窗口显示每一步的
类型、路径或远端，并允许逐项移除或整体清空。只有点击“确认并逐步执行”后，软件
才按顺序运行 Git 命令。

任何一步失败都会停止执行。成功步骤不会自动回滚，失败步骤和尚未执行的步骤继续
保留在计划中，详细日志记录每一步的开始、完成或错误。

提交步骤加入计划后，软件阻止继续添加本地文件修改步骤。需要继续修改时，先移除
提交步骤。危险删除需要勾选危险确认；清空远端还必须手动输入准确的
“项目全称/目标分支”。

## 视觉状态

- 支持跟随系统、浅色、深色三种显示模式；深色模式使用独立表面、边框和状态色。
- 提供经典绿、海洋蓝、星夜紫、琥珀金、玫瑰红五种配色方案，图标随强调色变化。
- 应用内品牌、窗口图标和发布程序包统一使用圆角矩形树形图标。
- 活动面板使用当前配色强调色边框和“粘贴目标”标签。
- 选中行使用当前配色强调色背景。
- 目录、Dart、文档和图片文件使用不同图标颜色。
- Git 状态使用 `M/A/D/R/U/NEW` 简短徽标。
- 空目录、读取错误和加载状态有独立占位内容。

## 文件右键菜单

右键单击文件行会将其设为当前活动面板的项目并显示菜单：

- 用文件资源打开：调用 Windows 资源管理器并定位、选中该文件；
- 用默认打开方式打开：交给 Windows 文件关联决定默认应用。

右键未选中文件时会先取消该面板的其它选择，只选中目标文件；文件夹行不显示
文件打开菜单。失败原因显示在 SnackBar 和详细日志中。

## 快捷键范围

资源快捷键通过窗口级键盘事件处理，因此不要求用户先点击某个可聚焦控件。
焦点进入底部提交说明输入框或模态对话框时，详细处理逻辑会避让文本编辑，
保证 `Ctrl+C`、`Ctrl+V` 仍按输入框的文本行为执行。

- `Delete`：打开批量删除确认；
- `Ctrl+Shift+U`：确认后推送当前分支。

## 主题

设置中的“跟随系统”是默认选项。Windows 切换到深色或浅色外观时，应用会立即同步。
用户也可以固定浅色或深色；选择持久化到软件目录的 `userdata/settings.json`。
“外观设置”中的配色方案同时影响应用品牌、按钮、选择状态、边框、图标和强调文字。

## 语言

设置中的“语言”页面提供：

- `Follow system / 跟随系统 / 跟隨系統`：默认选项，读取操作系统语言；
- `English`：使用英文界面；
- `简体中文`：使用简体中文界面；
- `繁體中文`：使用繁体中文界面。

每个固定语言选项的名称和说明均使用该语言自身文字。跟随系统选项只使用操作系统
实际语言显示名称和说明，例如英文系统只显示英文，不再同时展示三种语言。
English、简体中文、繁體中文分别保存为稳定的语言偏好值；保存设置后界面立即切换，
无需重启。

系统语言会识别 `zh-CN`、`zh-Hans`、`zh-TW`、`zh-HK`、`zh-MO` 和 `zh-Hant`。
不支持的系统语言回退到英文。

## 字体

字体默认选项是软件内置的 `Noto Sans SC / 思源黑体`。用户仍可切换为
“系统默认（自动适配）”，此时 Windows、macOS 和 Linux 分别使用 Flutter
与操作系统的原生默认字体。设置页分为“软件内置”和“系统自带”：

- 软件内置：Inter UI、Noto Sans SC、IBM Plex Sans；
- 系统自带：读取当前设备已安装字体；
- 搜索框可按名称、用途和描述实时筛选；
- 每个字体选项显示真实字体预览和选中状态。

字体预览即时更新，保存后整个应用使用所选字体。缺失字体会回退到系统字体。
字体大小只有 90%、100%、110% 三档，避免极小或极大字号破坏紧凑布局。
设置页内容超过可用高度时显示常驻滚动条；字体页顶部还会提示下方存在字体预览和
字体大小设置，避免被误认为页面没有内容。

设置窗口使用左侧分类导航，分为字体、语言、外观设置、单位设置和关于。
字体、语言、外观和单位共享同一个保存动作；关于页展示版本、项目仓库和人工智能
协作致谢。

关于页还提供“一键发送到桌面”。快捷方式优先指向稳定
`GitGuiExpandLauncher.exe`，工作目录设为软件根目录；Launcher 不存在时才回退到
当前应用程序路径。

## 删除与推送

删除按钮和 `Delete` 会把选中项目加入删除计划。计划确认时还要勾选危险确认。
已跟踪、未跟踪和忽略内容分别通过 `git rm` 与 `git clean` 处理。

推送按钮位于底部提交工作区，并与 `Ctrl+Shift+U` 共用当前分支计划。已配置 upstream
时执行 `git push`；否则优先推送至 `origin` 并设置 upstream。认证失败会同时显示在
提示和详细日志中。

## 分支管理

提交工作区的分支名称可打开分支管理窗口。窗口列出本地分支，并提供创建、切换、
重命名、安全删除和可选强制删除。分支动作先加入执行计划，危险删除仍需计划窗口
确认；当前分支不能直接删除。

## 多平台远端

提交工作区的“远端 N”按钮打开远端管理。对话框按 URL 自动识别 GitHub、Gitee、
GitLab、Bitbucket 或通用 Git，每个远端显示名称、平台和脱敏后的地址。

- 添加远端：输入名称和 HTTPS/SSH URL；
- 编辑远端：修改地址，远端名称保持不变；
- 删除远端：仅删除本地 remote 配置；
- 单项推送：选择指定远端；
- 全部推送：按顺序推送到所有 remote，并分别报告成功和失败。
- 清空远端历史：显示目标项目、分支和原引用清单，加入单独的高风险计划。

## 清空远端

清空远端会先通过 `git ls-remote --refs` 读取分支和标签。加入计划时显示完整引用
清单；执行计划需要勾选危险确认并输入准确的“远端项目全称/目标分支”，例如
`CY68GI/Git_Gui_Expand/main`。

执行时先把原引用抓取到本地 `refs/gitgui-expand/backup/<remote>`，再在不修改本地
工作区和索引的情况下创建空目录树与空根提交。提交说明包含日期、时间、项目名和
分支名，最后使用一次 atomic push 替换目标分支并删除其它 heads/tags。完成后远端
只有一个不含文件的分支提交。受保护分支、服务器不支持 atomic push、权限不足或
网络失败时会报告错误。

## 日志

顶部“操作日志”打开双标签查看器：

- 普通日志：启动、仓库打开、移动/复制/提交结果、警告和错误；
- 详细日志：普通日志内容，加上活动面板、选择、导航、键盘快捷键、设置、
  文件夹选择器、更新检查以及每条 Git 命令的参数、退出码、标准输出和错误输出。

日志文件位于软件目录 `userdata/logs`，查看器可以直接打开该目录。
普通日志和详细日志的新内容按当前界面语言生成；Git 命令原始输出和外部技术错误
保持原始文字，便于复制给 Git 平台排查。

## 自动更新

点击顶部“更新”会立即检查最新 Release。发现新版本时显示“立即更新并重启”：

- 下载阶段显示实时百分比；
- 校验、解压和准备阶段显示当前步骤；
- 新版本准备到 `versions/<版本>`，不会覆盖当前正在运行的版本；
- 准备完成后应用退出，常驻 Launcher 切换版本并重新打开；
- 更新过程保留设置、历史、日志和字体；
- 新版本未通过启动检查时，Launcher 自动恢复上一版本。
- 新版本通过 8 秒启动检查后，只保留当前新版本；
- 其他版本目录、下载的更新 ZIP、未完成下载和临时解压目录会自动删除，
  清理失败只记录到 Launcher 日志。

发布日期缺少 Windows x64 ZIP、SHA-256 或 `version.json` 时，只显示错误，不会修改程序。
“打开发布页”始终作为网络较慢或自动更新失败时的手动后备入口。
更新源可在 GitHub 与 Gitee 之间切换；Gitee Release 附带 SHA-256 文件供下载校验。

全新解压包缺少 `current-version.txt` 时，Launcher 会扫描 `versions`，恢复唯一
有效版本或最高语义版本；根目录平铺的 Release 文件也可以直接启动。版本标记兼容
UTF-8 BOM 和 UTF-16 BOM。

应用启动后还会主动执行维护扫描。若发现旧版本、旧安装包、未完成下载、临时目录或
旧平铺程序文件，会先自动清理；仍有剩余时弹出扫描窗口。关于页也提供手动
“扫描旧版本与安装包”和一键清除入口。

首次从旧版 PowerShell 更新架构迁移时，需要手动安装一次 Launcher 版本。`v0.8.1`
和 `v0.8.2` 的哈希校验依赖 Windows PowerShell 文本输出，请手动安装一次 `v0.8.3`；
之后从 `GitGuiExpandLauncher.exe` 启动即可使用多版本自动更新。

## 反馈

操作成功或失败通过浮动 SnackBar 显示。致命读取错误会保留在对应面板，
用户可以刷新或返回上一级恢复。

成功、失败和危险提示使用更大的固定正文字号、关闭按钮和更长的显示时间。
完整流程见应用内“指南”入口和 `docs/USER_GUIDE.md`。
