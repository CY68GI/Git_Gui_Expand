# Git GUI Expand 使用指南

語言：[English](USER_GUIDE.md) | [简体中文](USER_GUIDE.zh-CN.md) | 繁體中文

## 1. 先計畫，再執行

Git GUI Expand 不會在點擊移動、重新命名、刪除、提交、推送或清除遠端歷史後
立即修改儲存庫。所有操作會先加入待執行計畫。

1. 使用核取方塊選取檔案與資料夾。
2. 從工具列、右鍵選單、提交工作區或遠端管理加入操作。
3. 檢查待執行計畫。
4. 移除或清除不需要的步驟。
5. 確認後依序執行。

任何步驟失敗時會立即停止，失敗步驟與後續步驟仍保留在計畫中；已完成步驟不會
自動回滾。

執行前，軟體會重新檢查儲存庫根目錄、目前分支、HEAD、Git 狀態、遠端設定與受影響
路徑類型。後續步驟也會比對前一步完成後的狀態。若外部程式修改這些狀態，受影響
步驟不會執行。請查看「狀態變更詳情」，再按「重新整理儲存庫並重建計畫」。

## 2. 開啟儲存庫

點擊「開啟 Git 儲存庫」，Windows 會顯示標準「開啟」對話框。請選擇已包含
`.git` 的儲存庫根目錄。

「開啟空白資料夾」可選擇尚未包含 `.git` 的目錄。軟體會顯示包含目標路徑的
一次性初始化計畫；取消不會建立儲存庫，確認時會重新檢查 `.git` 仍不存在，再執行
`git init` 並開啟新儲存庫。

「複製 Git 儲存庫」可輸入 HTTPS、SSH 或本機網址，並選擇父目錄與專案資料夾名稱。
填寫視窗只建立複製預覽，取消不會建立檔案；確認計畫時會再次檢查父目錄與空目標，
再執行 `git clone` 並開啟複製後的儲存庫。

頂部「Git 中繼資料」可在未設定任何遠端時刪除 `.git`。這會永久刪除提交歷史、
分支、標籤、索引、Stash、參照、遠端設定和儲存庫層級 Git 設定，但工作檔案保留。
此操作會先作為獨立步驟加入待執行計畫；必須在計畫視窗輸入 `CLEAR GIT`
並確認執行。

開啟後可使用「專案目錄」在檔案總管中開啟目前專案。最近開啟記錄只保存通過
驗證且仍然存在的 Git 根目錄，最多保留十筆。

發布版本請使用 `GitGuiExpandLauncher.exe` 啟動。若全新解壓縮目錄缺少
`current-version.txt`，Launcher 會從唯一有效的 `versions/<版本>` 自動恢復；
根目錄直接包含 `git_gui_expand.exe`、`flutter_windows.dll` 與 `data` 的目錄
也支援直接啟動。

## 3. 左右雙欄檔案操作

左右資源面板瀏覽同一個儲存庫，但各自保存目前資料夾、載入狀態與選取項目。

- 點擊面板可將其設為貼上目標。
- 雙擊資料夾進入。
- 使用核取方塊選取一個或多個項目。
- 使用剪下 `Ctrl+X` 或複製 `Ctrl+C`。
- 進入目標資料夾後使用貼上 `Ctrl+V`。

移動、複製、重新命名與刪除都先加入計畫。

### 右鍵選單

檔案列右鍵可：

- 在檔案總管中定位並選取檔案；
- 使用 Windows 預設應用程式開啟。

### 重新命名

只勾選一個項目，點擊「重新命名」或按 `F2`，輸入新名稱並加入計畫。確認後使用
`git mv` 執行。

### 刪除

勾選項目後點擊「刪除」或按 `Delete`。加入計畫後必須勾選危險操作確認。
已追蹤內容使用 `git rm`；未追蹤或忽略內容使用 `git clean`。刪除後本軟體無法
直接復原。

## 4. 提交工作區

- 「暫存全部」會計畫執行 `git add -A`。
- 「取消暫存」會把索引恢復到 `HEAD`，保留工作區檔案。
- 「加入提交計畫」會先執行 `git add -A`，再執行 `git commit`。

填寫提交說明後檢查計畫。提交步驟加入後，新的檔案修改步驟會暫時被阻止，需先
移除或執行提交步驟。

加入提交計畫前，軟體會檢查目前有效的 Git 作者與提交者身分。缺少
`user.name` 或 `user.email` 時不會加入計畫；執行提交時還會在 `git add -A`
之前再次檢查。請在專案目錄執行：

```powershell
git config --local user.name "Your Name"
git config --local user.email "you@example.com"
```

若要為目前使用者設定預設身分，可將 `--local` 改為 `--global`。

### 分支管理

點擊提交工作區目前分支名稱可開啟「分支管理」，支援建立、切換、重新命名、
安全刪除已合併分支，以及在勾選強制選項後使用 `git branch -D` 刪除未合併分支。
所有分支操作都先進入執行計畫，確認後才執行；目前分支不能刪除。

### Stash 管理

點擊提交工作區的「Stash」可建立、套用、彈出或刪除 Stash，並可選擇是否包含
未追蹤檔案。所有操作先進入執行計畫；刪除 Stash 需要危險操作確認。

## 5. 推送與遠端

可管理 GitHub、Gitee、GitLab、Bitbucket 與一般 Git 遠端。

- 新增或修改遠端 URL。
- 移除本機遠端設定，不會刪除平台倉庫。
- 推送到單一遠端或全部遠端。
- 重新整理遠端清單。

推送會先加入計畫。已有 upstream 時執行 `git push`；否則優先使用 `origin` 並
設定 upstream。認證、網路或權限錯誤會回報為失敗。

同步視窗會顯示目前 upstream 與 ahead/behind 數量：

- 「取得目前 upstream」會計畫執行 `git fetch --prune <upstream 遠端>`；
- 「取得全部遠端」會依序嘗試所有遠端並逐項回報結果；
- Fetch 只會更新遠端追蹤引用，不修改工作區檔案；
- Fetch-all 部分失敗時，成功遠端的更新會保留，失敗遠端會單獨列出。

「安全快進 Pull」只有在目前分支已設定 upstream、工作區與索引乾淨、僅落後且沒有
待推送提交時才可用。執行時會先 Fetch，再重新計算 ahead/behind，並且只執行
`git merge --ff-only <upstream>`。

以下情況會拒絕 Pull：

- 工作區或索引有未提交變更；
- detached HEAD 或沒有 upstream；
- 本機與遠端歷史已分叉；
- 本機分支已領先或不需要 Pull。

若 Fetch 後才發現歷史分叉，遠端追蹤引用會保留為最新，但目前分支和工作區不會
變更。請先使用外部 Git 完成 Merge 或 Rebase，再回到軟體重新整理狀態。

## 6. 清除遠端歷史

這是高風險操作。指定遠端分支會被替換為一個空根提交，其他分支與標籤會刪除。
本機檔案會保留，但本機同名分支與索引會同步至空提交，重新整理後檔案顯示為
未追蹤。

執行前：

1. 本機目前分支必須與目標遠端分支相同。
2. 重新讀取遠端引用，並與確認時的引用和物件雜湊比較。
3. 檢查遠端引用清單。
4. 勾選危險操作確認。
5. 準確輸入 `擁有者/專案/分支`。

原引用會備份到 `refs/gitgui-expand/backup/<遠端>`。受保護分支、權限不足、
網路失敗或不支援原子推送的伺服器可能拒絕操作。推送會使用原子推送，並為目標
分支與每個待刪除引用設定 `--force-with-lease`；已知引用在確認後變更時會中止。

## 7. 設定

設定包含五個頁面：字型、語言、外觀、單位與關於。

### 語言

可選擇 English、简体中文、繁體中文或跟隨系統。選擇跟隨系統時，只顯示作業系統
實際語言的一種文字，不再同時顯示三種語言。

儲存設定後立即切換介面語言。之後產生的普通日誌與詳細日誌會使用所選語言；
Git 原始命令輸出與外部技術錯誤文字保持原樣。

### 字型與外觀設定

預設使用內建 `Noto Sans SC`。可搜尋內建或系統字型。字型頁面有常駐捲軸，並提示
下方還有字型預覽與字級設定。

字級限制為 90%、100%、110%。外觀設定可跟隨作業系統、淺色或深色，並提供
經典綠、海洋藍、星夜紫、琥珀金和玫瑰紅五種配色方案；按鈕、選取狀態、邊框和
圖示會跟隨配色方案。

### 桌面捷徑

開啟「設定 → 關於」，點擊「一鍵傳送到桌面」。若存在
`GitGuiExpandLauncher.exe`，捷徑會指向 Launcher，工作目錄設為軟體目錄。
關於頁也會顯示 `git_gui_expand.exe` 和 `GitGuiExpandLauncher.exe` 的實際版本。

## 8. 自動更新

更新頁會檢查 GitHub Release。點擊「立即更新並重新重啟」後，軟體會下載
Windows x64 ZIP、驗證 SHA-256、解壓縮到 `versions/<版本>`，結束目前程式後由
Launcher 切換版本並啟動。

新版本未通過啟動檢查時會自動回滾。更新成功後只保留目前版本；其他版本目錄、
下載的更新 ZIP、未完成下載、臨時解壓目錄和舊更新指令碼都會清除。

更新頁可選擇 GitHub 或 Gitee；中國大陸網路建議使用 Gitee。Gitee Release
同時提供 ZIP 和 SHA-256 校驗檔案。

應用程式啟動時也會主動清理，因為舊根目錄 Launcher 可能沒有最新清理邏輯。
新版本目錄包含維護用 Launcher；目前應用程式結束後，維護助手會重試取代根目錄
`GitGuiExpandLauncher.exe`。

開啟「設定 → 關於 → 掃描舊版本與安裝包」可手動掃描。視窗會列出舊版本、安裝包、
未完成下載、臨時目錄和舊平鋪程式檔案；點擊「一鍵清除」會刪除這些內容，
同時保留目前版本和 `userdata`。

若網路較慢或線上發布資料不可用，可使用「打開發布頁」。

## 9. 日誌

頂部「操作日誌」提供：

- 普通日誌：啟動、儲存庫、Git 操作、警告與錯誤。
- 詳細日誌：另含導覽、選取、設定變更、更新檢查，以及每條 Git 命令的參數、
  結束碼、標準輸出與錯誤輸出。

日誌保存在軟體目錄的 `userdata/logs`。

## 10. 快速鍵

`Ctrl+O` 開啟儲存庫。

`Ctrl+X` 記錄剪下選取。

`Ctrl+C` 記錄複製選取。

`Ctrl+V` 將貼上操作加入計畫。

`F2` 將重新命名加入計畫。

`Delete` 將刪除加入計畫。

`Ctrl+A` 全選目前資源面板項目。

`Ctrl+R` 重新整理儲存庫。

`Ctrl+Shift+U` 將目前分支推送加入計畫。

## 11. 安全建議

- 執行危險操作前先備份重要儲存庫。
- 檢查每個計畫路徑、分支、遠端與提交說明。
- 不要將清除遠端歷史當作一般清理操作。
- 清除遠端前先確認平台分支保護設定。
- 妥善保管 Git 認證資料與軟體目錄。
